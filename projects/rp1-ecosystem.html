RP1 Ecosystem

RP1 is the spatial-computing infrastructure the Foundation's planned metaverse presence would run on — and the honest headline is that nothing is running on it yet. Zero worlds are live on RP1. No fabric or service has ever been attached for AGI Corp. The six anchored fabric files are published on GitHub Pages, but the roughly 200 GLB assets and the map.wasm file they reference are not hosted, so they do not render fully in Artemis yet. This page covers the whole named stack — Sneeze, Rubidium, Artemis, VRS / Universal Map, RMAP, Statabase, and OMBI — and for each component it states what is verified and what is only a name on the live site.

What this is

RP1 is spatial-computing infrastructure: the servers, services, and software that would let people enter shared virtual worlds, move through them, and interact with them and with each other. In the Foundation's architecture it is the ground the metaverse presence would stand on. WorldForge, described on its own page, builds worlds; RP1 is where those worlds would run. The distinction matters, because a world can be built without being live, and a stack can be named without being attached. RP1, as verified today, is a named infrastructure with a named native browser, a named registry, and a set of named components — and with no live worlds, no attached fabrics, and no attached services for AGI Corp.

The stack's components are listed below, one by one, each with a verified column and a name-only column. The components closest to a user — the browser, the viewer, the map — carry the most verified detail, while the services named only on the live site carry the least. That pattern is normal for early-stage infrastructure; what this page refuses to do is present the naming as the building.

One fork in the Foundation's materials should be known to every reader. The filed entity is a nonprofit public benefit corporation — a different legal form: a filed nonprofit cannot offer equity, a SAFE, or a profit share, and it cannot be owned or controlled by a for-profit head. This site follows the filed status and notes the site label where relevant, rather than presenting the two as the same entity. Counsel would have to choose one track in writing before any solicitation. Being named on a website, in an internal list, or in a plan is not the same as being formed: a filing, a bank account, an EIN, a signed agreement, a customer, or a dollar of revenue would each be a separate, verifiable fact, and none is claimed here unless the page cites the document, the date, and the issuing authority.

The verified core

Five facts about RP1 are verified, and they are the frame for everything else on this page. First, RP1 is spatial-computing infrastructure. Second, Artemis is RP1's native browser, in early alpha version 0.4.3, desktop only. Third, VRS is a registry, and the Universal Map is the map that sits on it. Fourth, Spatial Fabrics are hosted on your own infrastructure — in the Foundation's case, on GitHub Pages — not hosted by RP1 as a service. Fifth, and most important, zero worlds are live on RP1: no world has been verified live there, and no fabric or service has been attached for AGI Corp.

Two further verified facts belong in the same frame. The Map Viewer is a database-backed editor, not a JSON renderer: it edits the database that holds map data, and it does not render a world from a JSON file. And the six anchored fabric JSONs are on GitHub Pages, but approximately 200 GLB assets and map.wasm are not hosted: the fabric files are reachable, the assets they reference are missing, and the worlds therefore do not render fully in Artemis yet.

The six anchored fabrics — and Biota, which has no series number

Six fabric files are published on GitHub Pages as the Foundation's anchored worlds: Cognition at 45.483, 18.572 (S01); Empathic at 47.440, -179.350 (S02); Diagnostic at 5.343, 101.566 (S03); Locator at 21.097, 142.693 (S08); the SmartCiti.X Holodeck at 39.846, -86.622 (S10); and Biota at -38.71260348427612, -27.248278366617797. Five of the six map to series. The sixth does not, and this page says so plainly rather than assigning it one.

Biota.blockchain has an anchored world, but no series number. Its fabric is published, its coordinates are verified, and it appears in the Foundation's materials as Biota.blockchain — but Biota does not appear in the April 2026 internal list of 33 named W3 sub-series, and no document reviewed for this site assigns it a series number. This site does not assign it one. Inventing a number for Biota would corrupt the series list, mislead anyone counting the series, and create a false mapping that later work would have to undo. Biota is therefore recorded here exactly as it stands: anchored, published, and unnumbered, with the gap flagged for resolution. The same discipline applies to the WorldForge coordinate sets: the first 41 worlds in the WorldForge set carry latitude and longitude values that differ from these agi-corp anchor coordinates, and the two sets must never be mixed in an RP1 attach.

All six fabrics share the same limit: their JSON files are live on GitHub Pages, but the roughly 200 GLB assets and the map.wasm file they reference are not hosted, so none of the six renders fully in Artemis yet. “Anchored” therefore means “defined and located”, not “live” and not “rendering”. The remaining 28 series have no anchored fabric verified at all.

What exists today vs what is planned

What exists today

  • RP1 as named spatial-computing infrastructure, with Artemis v0.4.3 (early alpha, desktop only) as its native browser and VRS as its registry.
  • Six anchored fabric JSONs on GitHub Pages, with verified coordinates, and ~200 GLB assets + map.wasm not hosted.
  • The Map Viewer as a database-backed editor.
  • The names Sneeze, Rubidium, RMAP, Statabase, and OMBI, as names on the live site.
  • Zero worlds live on RP1; no fabric or service attached for AGI Corp.

What is planned

  • Host the ~200 GLB assets and map.wasm, and verify a full render of at least one anchored fabric in Artemis.
  • Describe Sneeze, Rubidium, RMAP, Statabase, and OMBI in writing — what each does, and whether it is built — or withdraw the names.
  • Attempt a first RP1 attach, world by world, only after a render is verified, and publish the evidence.
  • Resolve Biota's missing series number with a document, not a guess.

No timeline is given for any of these steps, because no timeline is verified. Bringing a world to RP1 was authorised world by world and described as an urgent proof of concept, but authorisation is a permission, not a schedule, and no world has yet been reported live there.

What would have to happen next

Before anything on this page can be described as live, four things would have to happen, in order. First, the assets: the roughly 200 GLB files and map.wasm referenced by the six anchored fabrics would have to be hosted where the fabric files can reach them, and the hosting location recorded. Second, the render: a full render in Artemis would have to be verified and dated, with a screenshot or a log — for at least one fabric, and then for each of the others in turn. Third, the names: Sneeze, Rubidium, RMAP, Statabase, and OMBI would each have to be described in writing, with their function stated and their build status evidenced, so they stop being names and start being components — or the names would have to be withdrawn from the site. Fourth, the attach: a single world would have to be attached to RP1 and verified live, with the evidence published, before any claim of a live world could be made — and that first live world would be one world, not proof that the stack, the catalogue, or the network is live.

Until those steps are taken, the honest public record for the RP1 ecosystem is this page: a real browser in early alpha, a real registry, six anchored fabrics that do not yet render fully, five names that are only names, and zero worlds live on RP1.

How it would be governed

Governance for the RP1 ecosystem, as planned, follows the model used across the intended W3 network. Day-to-day work would be agent-managed: agents would operate routine work within limits set in advance by humans. Humans decide, humans sign, and humans move funds. Agents do not sign documents, do not move money, do not hire or fire, do not offer securities, and do not enact doctrine or charters. A human Steward Council would hold decision authority, set the limits inside which agents may act, review what agents did, and remain accountable. That separation is deliberate: the point of an agent-managed venture is not to remove human responsibility, but to make routine work faster while keeping consequential decisions in human hands.

That model is itself planned, not operating for this project: no Steward Council roster, operating agreement, or published set of agent limits exists to point to today. The Foundation's role in the intended structure is as mission steward, under written mission agreements, with its board remaining independent: a California nonprofit cannot be owned or controlled by a for-profit head. No agent message, draft, or page like this one is a commitment by the project or the Foundation; only a named human acting within signed, written authority can commit either one, and any future fundraising, partnership, or customer agreement would need its own documents, its own issuer, and counsel review.
